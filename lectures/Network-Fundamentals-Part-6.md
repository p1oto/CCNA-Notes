# Network Fundamentals - Part 6 (IPv4 Addressing - Part 2)

### 1. الوظيفة الحقيقية لقناع الشبكة (Subnet Mask Purpose)
* قناع الشبكة هو الفيصل الوحيد الذي يحدد هل جهازان يقعان في نفس الشبكة المحلية أم في شبكتين مختلفتين
* قاعدة المقارنة:
  * الخانات المقابلة لـ `255` في الماسك تمثل الـ Network ID وتكون ثابتة لجميع أجهزة نفس الشبكة
  * الخانات المقابلة لـ `0` تمثل الـ Host ID وتتغير لكل جهاز
* حالات عملية هامة:
  * **جهازان على كلاس C:**
    * جهاز 1: `192.168.1.10` بماسك `255.255.255.0`
    * جهاز 2: `192.168.2.10` بماسك `255.255.255.0`
    * النتيجة: يقعان في شبكتين مختلفتين (لا يتواصلان عبر السويتش بدون راوتر) لاختلاف الأوكتيت الثالث
  * **جهازان على كلاس B:**
    * جهاز 1: `172.16.1.5` بماسك `255.255.0.0`
    * جهاز 2: `172.16.2.100` بماسك `255.255.0.0`
    * النتيجة: يقعان في نفس الشبكة ويتواصلان مباشرة عبر السويتش لتطابق أول خانتين (`172.16`)

### 2. مقارنة العناوين الخاصة والعامة (Private vs Public IP)

**العناوين الخاصة (Private IP Addresses):**
* عناوين مخصصة للاستخدام الداخلي فقط داخل الشبكات المحلية (LAN) مجاناً
* حددتها منظمة IANA لمنع تكرار العناوين واستنزاف IPv4
* غير قابلة للتوجيه على شبكة الإنترنت العالمية (Non-Routable on Internet)
* النطاقات المحجوزة:
  * **Class A:** من `10.0.0.0` إلى `10.255.255.255`
  * **Class B:** من `172.16.0.0` إلى `172.31.255.255`
  * **Class C:** من `192.168.0.0` إلى `192.168.255.255`

**العناوين العامة (Public IP Addresses):**
* عناوين رسمية حقيقية تُستخدم للاتصال عبر الإنترنت العالمي
* يتم شراؤها وتأجيرها من منظمة IANA بواسطة مزودي خدمة الإنترنت (ISPs)
* فريدة عالمياً ومستحيل أن تتكرر لأكثر من خط إنترنت في العالم

---

### 3. تقنية ترجمة العناوين (NAT - Network Address Translation)
* شبكة الإنترنت العالمية ترفض التعامل مع أي Private IP
* آلية الخروج للإنترنت:
  1. مزود الخدمة (ISP) يمنح راوتر المستخدم Public IP واحد فقط على واجهته الخارجية
  2. جميع أجهزة الشبكة الداخلية التي تحمل Private IPs مختلفة تخرج إلى الإنترنت متخفية خلف هذا الـ Public IP الواحد
  3. الراوتر يقوم بعملية الـ NAT لتبديل العناوين أثناء خروج الداتا وعودتها للجهاز الطالب تحديداً

---

### 4. بروتوكول ARP وتفاصيل عمله (Address Resolution Protocol)
* الهدف الأساسي: الحصول على الـ Destination MAC Address المقابل لـ Destination IP معروف داخل نفس الـ Subnet
* متطلبات خروج أي Packet:
  * Source IP
  * Destination IP
  * Source MAC
  * Destination MAC
* خطوات تنفيذ الـ ARP:
  1. إذا كان Destination MAC مجهولاً، يرسل الجهاز طلب `ARP Request` بنظام **Broadcast** لجميع منافذ السويتش
  2. تسأل الرسالة: "من يمتلك هذا الـ IP؟ أرسل لي الماك أدرس الخاص بك"
  3. جميع الأجهزة تتجاهل الرسالة وتسقطها (Drop) عدا الجهاز صاحب الـ IP المعني
  4. يرد الجهاز المستهدف برسالة `ARP Reply` بنظام **Unicast** موضحاً الماك أدرس الخاص به
  5. يسجل الجهاز المرسل العنوان في جدول الـ `ARP Cache` لتكتمل بيانات الفريم ويتم الإرسال بنجاح
